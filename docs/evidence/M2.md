# M2 실행 증거

- 마일스톤: M2 — 명시적 stable Expo SDK와 Bun scaffold
- 실행 기간: 2026-08-24 ~ 2026-08-25 (Asia/Seoul)
- 상태: 완료 — 사용자 `G-M2-FINAL approve_completion` 승인(2026-08-25); local commit과 M3
  시작은 M2 완료와 별도 절차
- 증거 원칙: 사용자가 직접 공유한 명령 결과와 에이전트의 정적 검사를 구분하며,
  실행하지 않은 runtime·native 검사를 PASS로 표현하지 않는다.

## 1. 승인된 실제 template 기준선

M1에서 SDK 57 line을 승인한 뒤, 사용자가 repository 밖의 임시 디렉터리에
`default@sdk-57` template을 생성했다. 에이전트가 실제 attempt-01을 조사하고 사용자가
route·version·통합 manifest를 승인했다.

| 항목 | 실제 통합 값 |
|---|---:|
| Expo | `~57.0.16` |
| React Native | `0.86.2` |
| React | `19.2.3` |
| Expo Router | `~57.0.16` |
| TypeScript | `~6.0.3` |
| Bun | `1.3.13` |
| Node.js | `22.23.2` |
| entry | `expo-router/entry` |
| route root | `src/app/` |

`app.json`의 `typedRoutes: true`, `reactCompiler: true`, Expo Router plugin과 template
placeholder를 그대로 유지했다. iOS bundle identifier, Android package name과 EAS project
ID는 만들지 않았다. 자세한 결정 근거는 [ADR 0001](../adr/0001-expo-sdk-57-default-template.md),
[ADR 0002](../adr/0002-bun-only-package-management.md)와
[ADR 0003](../adr/0003-m2-bootstrap-quality-evidence-deferment.md)에 있다.

## 2. 사용자 실행 명령 게이트

| 게이트 | 실행일 | 실행 주체 | 공유된 결과 | 판정 |
|---|---|---|---|---|
| 외부 임시 scaffold | 2026-08-24 | 사용자 | `default@sdk-57` download·extract 성공, attempt-01 path 보고 | PASS |
| 최초 dependency install | 2026-08-24 | 사용자 | Bun `1.3.13`, 606 installs/580 packages 확인, exit `0` | PASS |
| validation run-01 | 2026-08-24 | 사용자 | Expo doctor `21/21` PASS, TypeScript TS2307·TS2882 RED | FAIL 후 remediation |
| CSS type-entry remediation | 2026-08-24 | 사용자 승인·에이전트 적용 | exact `src/types/expo.d.ts` 한 파일, 정적 무결성 검사 통과 | PASS |
| validation run-02 | 2026-08-25 | 사용자 | Expo doctor `21/21`, `bunx tsc --noEmit` exit `0` | PASS |
| Expo Go runtime smoke | 2026-08-25 | 사용자 | `bun run start`; iOS Simulator와 ADB Android target에서 default template 확인 | PASS — Expo Go만 해당 |

두 validation 명령은 사용자가 Nix devShell에서 직접 실행했다. Run-02는 doctor exit가
`0`인 경우에만 TypeScript를 실행했고, 공유된 개별 exit status는 둘 다 `0`이다.
에이전트는 이 두 명령을 대신 실행하거나 성공을 추정하지 않았다.

Runtime smoke도 사용자가 직접 실행하고 결과를 공유했다. 이는 SDK 57 default template,
Metro, route와 asset이 Expo Go의 precompiled native runtime에서 양 플랫폼에 표시됨을 확인한다.
`expo-dev-client`가 포함된 Development Build, CNG prebuild 또는 native binary build 결과로
해석하지 않는다.

## 3. 통합과 dependency 증거

- 승인된 scaffold 파일 49개와 디렉터리 13개만 no-clobber 방식으로 통합했다.
- Expo Go smoke 뒤 `src/app/index.tsx`에 동작 변화 없는 quote-formatting drift가 발견됐다.
  사용자가 `G-M2-INDEX-INTEGRITY restore`를 승인해 SDK 57 template 원본 해시로 복원했고,
  49개 파일과 13개 디렉터리 전체 재검사가 mismatch 0으로 통과했다.
- 생성된 nested `.git/`과 npm 명령을 전제로 한 template README는 통합하지 않았다.
- `package.json`의 generated dependency·script map은 유지하고
  `packageManager: bun@1.3.13`만 추가했다.
- project lockfile은 `bun.lock` 하나다. `package-lock.json`, `npm-shrinkwrap.json`,
  `yarn.lock`, `pnpm-lock.yaml`, `bun.lockb`는 없다.
- `bun.lock`의 root dependency와 devDependency map은 `package.json`과 일치한다.
- M3 전용 dependency인 `expo-dev-client`, TanStack Query와 Zustand는 추가하지 않았다.

핵심 SHA-256은 다음과 같다.

| 파일 또는 manifest | SHA-256 |
|---|---|
| historical integration destination digest | `09fdeb0c28737f45033039e93f15f71517bd9275773d0190f8300eb01c755ca6` |
| `package.json` | `5f9eed08a2259c52698dbdcc9a1edd47920faf03ed3fa939191812b83d1c327c` |
| `bun.lock` | `6c86f7448eb2f8cf41df1c35af7a5f10b2792efb7a86e652ee3ce7ec88f4f6ef` |
| `app.json` | `b3e597fab950627f12e2f5a24405fd22cb71255e4190ae32501e951906430750` |
| `tsconfig.json` | `2c427a7bc50569dc5167d39425793d8bba22eeffcb213fff05f6274980784508` |
| `.gitignore` | `47014f4d1be72742e6ec1cd53e8e7ce903cd8e1465a4c85abb9c5d91f1e92264` |
| `src/types/expo.d.ts` | `57d45be957186273b21383b09f6a6aa3ca599b28d1fb742fb3edfac464504b90` |

Historical integration digest의 canonical serialization algorithm은 별도로 보존되지 않아 현재
무결성의 단독 증거로 사용하지 않는다. 현재 판정은 inspection artifact에 보존된 49개 각
경로의 expected SHA-256을 실제 파일과 하나씩 대조하고 13개 디렉터리 존재를 확인하는 방식으로
재현한다. 복원 뒤 결과는 49/49 files, 13/13 directories, mismatch 0이다.

최종 user validation 전후 repository status SHA-256은 모두
`dfc84f01463784763ce8881016d9abcd1532559fa8c314140b3ad59cef53e602`였고 path count도
55개로 같았다. 핵심 파일 해시, Git index, 금지 경로 inventory도 변하지 않았다.

## 4. TypeScript 실패와 복구

첫 TypeScript 검사는 `src/components/animated-icon.web.tsx`의 CSS module과
`src/constants/theme.ts`의 global CSS import에 선언이 없어 실패했다. Expo CLI가
`expo-env.d.ts`를 Metro/start lifecycle에서 생성하지만, validation run-01 시점에는 Expo
runtime 실행이 아직 승인되지 않아 깨끗한 checkout의 compiler가 `expo/types`를 읽지 못한
것이 원인이었다.

사용자가 `G-M2-TSC-CSS-TYPES-REMEDIATION approve`로 exact path와 content를 승인한 뒤
`src/types/expo.d.ts`에 Expo의 기존 ambient type entry를 한 줄 추가했다. Dependency,
`tsconfig.json`, `app.json`, `.gitignore`와 generated source는 바꾸지 않았다. 에이전트의
정적 검사는 target hash, 49개 scaffold file, dependency/config map, Git index와 금지 경로를
확인했고, 사용자의 run-02 TypeScript exit `0`이 GREEN 회귀 증거다.

## 5. 보존 경계와 외부 영향

- 기존 `.agents/`, `.claude/`, `.codex/`, `AGENTS.md`, Nix toolchain과 Git history를
  template으로 덮어쓰지 않았다.
- 사용자 Expo Go smoke 뒤 ignored runtime 산출물인 `.expo/`와 root `expo-env.d.ts`가
  생성됐다. 두 경로는 commit 대상이 아니다.
- `ios/`, `android/`, `eas.json`은 여전히 없으며 CNG 생성물을 source control에 넣지 않는
  경계가 유지됐다.
- 사용자는 Expo start와 iOS Simulator·ADB Android target launch를 실행했다. Expo prebuild,
  Development Build, native binary build, signing과 store 제출은 실행하지 않았다.
- Production identifier, EAS project·credential과 remote resource를 생성하지 않았다.
- 기존 PWA, `jamye-server`, homelab, App Store Connect와 Play Console을 변경하지 않았다.
- Git add, commit, push와 remote write를 실행하지 않았다.
- 현재 M2 변경은 아직 commit되지 않았고 migration·remote side effect가 없다. 되돌려야 한다면
  별도 사용자 결정 뒤 이 문서에 열거된 M2 working-tree 변경만 버리면 M1 기준선
  `6cead618bccdc9967424126063f96ef41fa49797`로 돌아가며 별도 data rollback은 필요 없다.

## 6. 이 증거가 아직 보장하지 않는 것

- `bun run lint`와 test coverage: M2 template에는 작동하는 lint·test/coverage 구성이 없으며
  실행 결과를 가장하지 않는다. M2 전용 유예와 M3 이관 조건은 ADR 0003에 기록했다.
- Expo Development Build의 template runtime, `expo-dev-client`, CNG prebuild와 양 플랫폼
  native build
- 앱 구조, environment validation, error boundary, logger와 provider composition
- SQLite, contract, chat UI, outbox, realtime/delta 복구
- Production auth, push, media, signing과 store 제출

Development Build와 앱 기반 구조는 M3 이후, full native smoke와 E2E는 M7 이후의 별도
사용자 게이트다. M2 완료, local commit과 M3 시작은 서로 다른 사용자 결정으로 남는다.

## 7. Ultrawork 독립 검토와 남은 게이트

각 review는 서로 다른 fresh Claude context에서 현재 파일과 durable evidence를 다시 읽었다.

| 단계 | 검토 | 결과 | 비고 |
|---|---|---|---|
| VERIFY 6 | alignment | PASS | LOW 1, 승인된 CSS type recovery 경로 확인 |
| VERIFY 7 | safety | PASS | LOW 1, 사용자 명시 실행 때만 동작하는 template reset helper |
| VERIFY 8 | regression | PASS | finding 없음 |
| REFINE 9~13 | size·reuse·cascade·consistency·dead code | PASS | product 변경 없는 검증된 no-op |
| SHIP 14 | quality | PASS | LOW 1; lint·coverage 미측정 사실을 그대로 유지 |
| SHIP 15 | UX scope | PASS | LOW 1; demo의 npm 안내 문구는 후속 화면 교체 때 처리 |
| SHIP 16 | cascade | PASS | finding 없음 |
| SHIP 17 | final readiness | PASS | rollback 경계 LOW 문구를 이 문서에 반영 |

독립 검토에는 CRITICAL, HIGH, MEDIUM finding이 없다. TypeScript는 실제 GREEN이지만 M2에는
작동하는 lint 구성과 test/coverage harness가 없고 실행 결과도 없다. 따라서 M2의 lint와
coverage는 계속 `미측정`이며 PASS로 바꾸지 않는다.

사용자는 2026-08-25에 `G-M2-SHIP-REMEDIATION governance`를 승인했다. 이에 따라 SDK 57
bootstrap에만 한정한 품질 증거 유예를 적용하고, 실제 lint exit `0`, 의미 있는 test harness,
선언된 coverage denominator와 측정 aggregate coverage 80% 이상을 M3 완료 조건으로 강제
이관한다. 빈 test suite나 generated template 전용 test는 조건을 충족하지 않는다. 이 결정은
전역 Ultrawork 기준을 바꾸거나 M3 이후에 재사용할 수 없으며 자세한 자격·만료 조건은
[ADR 0003](../adr/0003-m2-bootstrap-quality-evidence-deferment.md)에 있다.

따라서 M2는 측정하지 않은 품질 검사를 통과로 주장하지 않은 채 최종 사용자 완료 판단으로
이동할 수 있었고, 사용자는 2026-08-25에 `G-M2-FINAL approve_completion`으로 M2 완료를
승인했다.

Governance 반영 뒤 세 fresh read-only reviewer가 현재 durable artifact와 repository state를
독립적으로 재검토했다.

| 검토 | 최종 판정 | Findings |
|---|---|---|
| M2-only scope·M3 hard carry-forward | PASS | CRITICAL 0, HIGH 0, MEDIUM 0, LOW 0 |
| 품질 주장·적용 자격·49/13 무결성 | PASS | CRITICAL 0, HIGH 0, MEDIUM 0, LOW 0 |
| README·roadmap·ADR·evidence cascade | PASS | CRITICAL 0, HIGH 0, MEDIUM 0, LOW 0 |

Quality reviewer가 처음 보고한 자격 조건 shorthand와 historical aggregate digest 감사 가능성
LOW 두 건은 국소 수정했다. Targeted recheck는 두 건이 해결됐고 새 finding이 없음을 확인했다.
검토는 install, build, runtime, native 또는 Git write를 실행하지 않았다.

Local commit과 M3 시작은 M2 완료 결정에서도 자동으로 파생되지 않는 별도 사용자 게이트다.
이 완료 승인은 Git add/commit/push, Development Build, native build 또는 M3 작업을 승인하지
않는다.
