# M4 실행 증거

- 마일스톤: M4 — local bootstrap contract와 SQLite foundation
- 실행 기간: 2026-08-29 ~ 2026-08-31 (Asia/Seoul)
- 상태: M4 종료 승인 — 구현·품질·Expo·양 플랫폼 native 증거와 VERIFY/REFINE/SHIP PASS, local closure commit 승인·push 미승인
- 시작 기준점: `a54ce89acd19fbaddec62b3539e179331a8b9133e`
- 증거 원칙: 사용자가 직접 공유한 명령 결과, 에이전트의 정적 검사, 실행하지 않은 범위를 구분한다. 실패한 중간 결과를 삭제하거나 PASS로 바꾸지 않으며 message body·비밀값은 기록하지 않는다.

## 1. 범위와 현재 판정

M4는 M3의 Development Build/CNG 기반 위에 다음 두 로컬 경계만 추가한다.

1. `expo-sqlite` 기반의 forward-only migration, 정확히 다섯 개의 domain table, injectable repository와 transaction 경계
2. production server에 bind되지 않은 `bootstrap.v2` OpenAPI/realtime schema, deterministic generation/check와 validated event mapper

화면은 여전히 deterministic `local-fixture`를 사용한다. M4 database와 wire boundary는 UI나 실제 HTTP·WebSocket·auth에 연결하지 않았다. M5의 chat read/write와 M6의 outbox dispatch·realtime·delta 실행을 앞당겨 완료한 것으로 보지 않는다.

최종 사용자 실행 aggregate는 모두 PASS다. 최초 fresh CCR에서는 Safety와 Regression이 PASS였고, Alignment는 이 문서가 없다는 이유 하나로 HIGH를 기록했다. 이 문서와 exact allowlist를 추가한 뒤 사용자 focused 검증이 모두 통과했고, fresh isolated Alignment 재검토도 CRITICAL/HIGH 없이 PASS했다. 이어진 Reusability와 Consistency review도 finding 없이 PASS했고, Steps 9/11/13은 size·cascade·dead-code를 대조한 뒤 speculative churn을 피하는 no-change refinement로 완료했다. SHIP의 Quality·UX·Cascade·Readiness 네 기술 검토도 finding 없이 PASS했다. 사용자는 `G-M4-SHIP approve_complete`와 `G-M4-COMMIT`으로 M4 완료 및 exact 40-path local closure commit을 승인했다. Push, PR, remote write와 production deployment는 승인하지 않았다.

## 3. SQLite migration과 repository 증거

구현 경계는 다음 불변식을 유지한다.

- migration 전에 WAL과 foreign keys를 설정한다.
- registry version은 중복 없이 1부터 연속이어야 하며, device version이 registry보다 새로우면 mutation 없이 실패한다.
- migration DDL과 `user_version` 증가는 하나의 exclusive transaction에 있고 실패 시 둘 다 rollback한다.
- domain table은 `conversations`, `messages`, `outbox_commands`, `applied_events`, `sync_cursors` 다섯 개뿐이다.
- pending message와 outbox command, canonical event와 message/cursor 반영은 각각 atomic boundary를 사용한다.
- runtime 값은 bind parameter로 전달하며 cursor는 단조 증가한다.
- exact duplicate event는 no-op이고, unknown valid event는 한 번 기록한 뒤 local `request_delta` 결과만 반환한다.
- post-commit subscriber 예외는 이미 commit된 repository operation을 reject하거나 이후 subscriber를 막지 않는다.

## 4. Bootstrap contract와 drift 증거

현재 contract는 `status = bootstrap`, `contract_version = bootstrap.v2`, `source_kind = repository-local-bootstrap`이다. `server_tag`와 `server_commit`은 의도적으로 `null`이며 production URL, credential, auth 또는 active transport를 포함하지 않는다. REST path-major는 `/bootstrap/v1/...`로 유지되며 local contract revision과 별개의 식별자다.

검증된 동작은 다음과 같다.

- anonymous local REST operation은 message command와 conversation delta 두 개뿐이다.
- known `message.upsert`는 validated snake_case wire value에서 typed repository shape로 map된다.
- optional additive field는 허용되고 unknown event type은 crash 없이 기록되며 recovery data로 `request_delta`를 반환한다.
- required field 누락과 음수 timestamp는 repository mutation 전에 invalid로 거부된다.
- canonical JSON, source/fixture hash, generator/validator identity, breaking shape가 manifest와 `contract.lock`에 고정된다.
- generated TypeScript는 REST event instance와 open payload, distinct known payload schema를 compile probe로 검증한다.
- `no-manual-rest-dto` architecture rule은 generated output 옆의 hand-maintained REST DTO를 거부한다.

주요 실행 증거는 다음과 같다.

| Contract RED | 3 suites, 14 tests가 source/generated boundary 부재로 실패 | 의도된 RED |

README의 bootstrap status/version, nullable server provenance와 production replacement condition은 최종 manifest/lock과 일치한다. Production contract 교체는 authenticated source ownership, non-null server tag/commit, 승인된 auth/endpoint 범위, regenerated artifacts와 compatibility review, 별도 M6 integration 결정이 모두 있어야 한다.

## 9. 이 증거가 보장하지 않는 것

- M4 repository를 사용하는 chat list/composer, optimistic UI 또는 실제 local send flow
- outbox network dispatch, HTTP, WebSocket, realtime subscribe, delta 호출, reconnect/restart recovery
- auth/session/token/SecureStore, production endpoint 또는 실제 server provenance
- public custom scheme, universal link 또는 app link의 production 계약
- automated chat E2E, Maestro, 실기기 acceptance, 성능·메모리·접근성 측정
- production identifier, signing, credential, store 제출, deployment 또는 remote resource
- dependency vulnerability audit 결과
- Terraform 또는 다른 infrastructure-as-code 구현

Native smoke는 현재 Development Build와 `local-fixture` startup을 확인했을 뿐, unwired SQLite repository를 UI에서 실행한 증거가 아니다.

## 10. 승인된 SCM 경계

1. `G-M4-COMMIT`은 이 문서의 exact 40-path local closure commit만 승인한다.
2. Push, PR, remote write, production signing·deployment는 별도 사용자 지시 전까지 금지한다.

이 문서는 자신을 포함하는 closure commit의 사전 감사 상태를 기록한다. 최종 commit hash는 SCM 실행 결과에서 별도로 보고하며, push는 별도 사용자 지시가 있어야 한다.
