# M3 실행 증거

- 마일스톤: M3 — 앱 기반 구조와 품질 경계
- 실행 기간: 2026-08-26 ~ 2026-08-28 (Asia/Seoul)
- 상태: 종료 감사 PASS — 구현·품질·양 플랫폼 fixture smoke 증거 수집과 사용자 최종 승인 완료
- 구현 체크포인트: `a451b91af3598ce0df7c64d8e0b3d25a65f3dedc`
- 증거 원칙: 사용자가 직접 공유한 명령 결과와 에이전트의 정적 검사를 구분한다. 실행하지 않은
  production·chat E2E·실기기 검사를 PASS로 표현하지 않는다.

## 1. 종료 감사 범위와 판정

이번 감사는 [로드맵의 M3 완료 증거](../roadmap.md)와
[ADR 0004](../adr/0004-m3-app-foundation-and-preference-deferral.md)의 경계를 기준으로 했다.
검토 범위는 Development Build/CNG 기반, strict environment validation, module/import boundary,
Error Boundary, redacted logger, system theme, deterministic local fixture, 품질 harness와 Nix-owned
Android native workflow다.

현재 판정은 **PASS**다.

- CRITICAL: 0
- HIGH: 0
- MEDIUM: 0
- LOW residual: 3개 build/tooling warning 묶음과 historical documentation reference 분류
- M3 완료 조건: 모두 충족한 것으로 감사됨
- 최종 마일스톤 결정: 사용자가 2026-08-28에 M3 완료를 승인

M3 smoke는 인증·서버·SQLite·chat 기능이 없는 exact `local-fixture` 화면만 검증한다. 따라서
로드맵 M7의 완성된 채팅 E2E, Maestro, reconnect/restart 검증 또는 실기기 acceptance를 앞당겨
완료한 것으로 보지 않는다.

## 5. CNG, native build와 runtime smoke

### 5.1 Clean regeneration

사용자는 승인된 hash와 repository-root guard가 붙은 recovery card에서
`bun run expo:prebuild:clean`을 실행했다.

- ignored `android/`, `ios/`를 삭제하고 다시 생성
- `package.json` 변경 없음
- CocoaPods 설치 완료
- 생성 뒤 `ios/Podfile`과 `android/build.gradle` 존재 확인
- 생성물은 Git에 추가하지 않음

### 5.2 Android

1. `bun run android:avd:start`가 exact `jamye_pixel_9_api_36`을 시작했다.
2. strict preflight 재실행은 `45 passed, 0 failed`였다.
3. `bun run expo:run:android`는 `BUILD SUCCESSFUL`, exit `0`으로 끝났다.
4. debug APK가 `jamye_pixel_9_api_36`에 설치되고 development-client deep link가 열렸다.
5. 사용자가 Metro 연결 뒤 현재 `local-fixture` 화면과 production server 미연결 안내를 확인했다.

AVD, Emulator, API 36.1 ARM64 Google Play image revision 4, Pixel 9 skin, CMake 3.22.1,
NDK 27.1.12297006과 Build Tools 36.0.0/35.0.0은 Nix/JSON SSOT에서 공급한다. Mutable AVD와
Gradle state는 repository와 Nix store 밖 project-specific XDG root에 있다.

### 5.3 iOS

1. `bun run expo:run:ios`는 `Build Succeeded`, exit `0`으로 끝났다.
2. 결과는 0 errors, 1 non-blocking build-phase warning이었다.
3. `JamyeDevelopment.app`이 iPhone 17 Simulator에 설치되고 development-client deep link가
   열렸다.
4. 사용자가 Metro 연결 뒤 Android와 같은 exact `local-fixture` 화면을 확인했다.

초기 smoke 시도 한 번은 `simctl openurl` timeout(code 60)이 발생했지만 같은 development
client 재시도에서 정상 연결됐고, dependency refresh·clean prebuild 뒤의 최종 iOS build/open도
exit `0`으로 끝났다. Timeout을 build 성공으로 바꾸어 기록하지 않고 최종 recovery 결과와
구분한다.

### 5.4 Cleanup

| 명령 | 공유된 결과 | 판정 |
|---|---|---|
| `bun run android:gradle:stop` | project Gradle daemon 1개 종료 | PASS |
| `bun run android:avd:stop` | exact `jamye_pixel_9_api_36` (`emulator-5554`) 종료 | PASS |

Stop은 AVD userdata·snapshot을 지우지 않았고 다른 Emulator를 종료하지 않았다.

## 7. 종료 감사와 residual risk

에이전트의 read-only/static closure audit 결과는 다음과 같다.

- checkpoint staged diff의 whitespace 검사와 high-confidence secret scan 통과
- `.env`, `.env.local`, credential/key 형식 파일이 checkpoint에 없음
- tracked `ios/`, `android/` path 0개
- checkpoint 뒤 working tree clean
- source/test/tool 범위에서 unresolved `TODO`·`FIXME` 없음
- current package dependency에서 Expo Router 외 navigation owner, UI framework, SQLite,
  TanStack Query와 Zustand 없음

남은 LOW residual은 다음과 같다.

1. Android build는 Nix SDK의 `ndk-bundle` compatibility link 위치에 관한 CXX5304 warning과
   Gradle 10 비호환 deprecation warning을 출력했다. 같은 build는 exit `0`이고 pinned NDK
   metadata·toolchain preflight가 통과했으므로 M3 blocker가 아니며 SDK/Gradle upgrade 때
   재평가한다.
2. iOS build는 Expo Dev Launcher의 script dependency analysis warning 1개를 출력했다. 0 errors,
   app install/open 성공이므로 M3 blocker가 아니며 upstream/native project 정책 변경 때
   재평가한다.
3. Repository-wide `oma docs verify "docs/**/*.md" --json --no-urls`는 historical M2 command·
   제거된 M2 template path와 sibling `jamye-plz` source path 13개를 현재 repository reference로
   분류해 exit `1`이었다. Accepted M2 evidence를 현재 파일로 고쳐 쓰지 않는다. 이번에 새로
   작성하거나 갱신한 `README.md`, `docs/roadmap.md`, local work plan과 이 M3 evidence는 각각
   targeted verification exit `0`, broken reference 0이었다.

Dependency vulnerability audit, cold-start/app-size/memory profile, VoiceOver·TalkBack, Maestro와
실기기 검사는 M3 완료 조건으로 실행하지 않았다. 이는 PASS 항목이 아니며 제품 기능이 구현된
M7/M8 release-facing 검증에서 다룬다.

## 8. 이 증거가 보장하지 않는 것

- SQLite schema, migration, repository 또는 database source of truth
- 실제 chat list, composer, optimistic message와 outbox
- REST, WebSocket, delta sync, reconnect와 restart recovery
- 실제 server contract, auth, session, token lifecycle와 production endpoint
- persisted theme/user preference 또는 generic state library 선택
- automated mobile E2E, Maestro, 실기기 acceptance와 성능·접근성 측정
- production identifier, signing, credential, store 제출과 remote deployment

이 항목은 M4 이후의 별도 설계·dependency·build·실행 승인 게이트다.

## 9. 최종 승인 경계

M3 implementation checkpoint는 local commit으로 보존됐고, 종료 evidence·roadmap 정리와 최종
code/repository 검사를 거쳐 사용자가 2026-08-28에 마일스톤 완료를 승인했다.

이 승인은 push, PR, remote write, M4 시작 또는 새 dependency 설치를 자동 승인하지 않는다. M4
schema, dependency, contract 또는 application 구현은 별도 사용자 승인 뒤 시작한다.
