## 1. 범위와 종료 판정

M5는 M4의 SQLite와 unbound `bootstrap.v2` 경계 위에 인증 없는 fixture 대화방 하나의 local
chat read/write를 구현했다.

1. 화면은 SQLite repository를 유일한 메시지 원본으로 읽는다.
2. 명시적 전송 버튼은 pending message와 queued outbox command를 하나의 exclusive SQLite
   transaction에 기록한다.
3. 실패 재시도는 새 identity를 만들지 않고 기존 `client_msg_id`와 outbox command를 재사용한다.
4. Virtualized list는 과거 page prepend anchor와 committed local message reveal을 구분한다.
5. iOS와 Android 모두 native keyboard progress를 animation authority로 사용해 composer와
   latest message를 같은 프레임에서 이동한다.
6. 전송 후 keyboard focus를 유지하면서 새로 commit된 메시지를 현재 keyboard viewport에 표시한다.

최종 판정은 **PASS**다. 사용자가 양 플랫폼에서 keyboard open과 local send 동작을 직접
수용했고, 최종 aggregate·dependency·architecture·native integration·runtime database 증거가
모두 확보됐다. 이 판정은 network dispatch, realtime/delta, reconnect/restart 수렴, auth,
production server나 자동 mobile E2E를 완료했다는 뜻이 아니다. 이들은 M6 이후의 별도 게이트다.

## 3. 데이터와 상태 소유권

### 3.1 읽기 경계

- `src/core/database/database-provider.tsx`가 database open, migration, repository 생성과 fixture
  seed를 소유한다.
- `src/features/chat/use-chat-conversation.ts`는 repository snapshot과 subscription을 통해
  initial page, older page, loading/error/empty 상태를 제공한다.
- Route와 screen은 SQLite implementation이나 HTTP client를 직접 import하지 않는다.
- M3의 in-memory development fixture screen과 test는 제거됐고, fixture identity와 notice는
  `src/features/chat/model/chat-fixture.ts`로 이동했다.
- M3에서 이어받은 notice의 정확한 문구는
  `로컬 개발용 fixture 데이터입니다. production server에 연결되어 있지 않습니다.`다.
  `chat-fixture.ts`가 이 copy를 소유하고 `src/features/chat/ui/chat-screen.tsx`가 화면에
  렌더링한다. `tests/app/thin-routes.test.tsx`는 `LOCAL_FIXTURE_NOTICE`의 exact string과 실제
  index route wiring을 함께 검증해 production 연결로 오인시키는 drift를 막는다.

### 3.2 쓰기와 재시도 경계

- `enqueuePendingMessage`는 message와 outbox command를 하나의 exclusive transaction으로
  기록하고 commit 뒤에만 subscriber에 알린다.
- 중간 write가 실패하면 optimistic message와 outbox 모두 rollback한다.
- 전송 결과는 committed local identity를 UI에 반환하며 list는 그 identity가 실제 row와
  settled content metrics에 나타난 뒤에만 reveal한다.
- Failed-message retry는 기존 identity와 command를 재사용한다. 새 message나 command를 중복
  생성하지 않는다.

### 3.3 M6와의 경계

새 local send는 `queued` 상태로 생성한다. M5에는 processor의 `in_flight`·`acked` 전이와
network drain이 없다. Failed fixture와 `failed` → `queued` retry 상태만 local retry 계약으로
모델링한다. Backoff, network regain, HTTP, WebSocket, delta 호출, canonical event apply와
restart convergence는 구현하지 않았다. Local fixture notice도 production server에 연결되지
않았음을 명시한다.

### 7.5 사용자 수동 관찰

사용자는 iPhone 17 Simulator와 Pixel 9 API 36 Emulator에서 다음을 직접 확인하고 양 플랫폼
동작을 수용했다.

- keyboard가 열릴 때 composer와 latest message가 keyboard 속도에 맞춰 부드럽게 함께 이동
- latest message가 composer 바로 위에 유지
- Android의 이전 stepped scroll/offset 불일치가 해소
- iOS의 이전 keyboard-open anchor 누락이 해소
- 전송 뒤 keyboard가 유지되고 새로 commit된 message가 현재 viewport에 표시
- 한국어 IME와 multiline 입력, light/dark 화면이 정상 동작

이 수동 관찰은 Simulator/Emulator 결과다. 실제 iPhone/Android 물리 기기 검증으로 확대해
표현하지 않는다. M5의 사용자 수용은 local-send와 native keyboard/list 기능에 한정한다.
VoiceOver/TalkBack, 200% text와 reduce motion은 실행하지 않았으며 M8 또는 별도 device
acceptance에서 확인할 `NOT RUN` 항목이다.

### 11.1 운영 rollback 경계

M5는 SQLite schema migration을 추가하지 않았고 `user_version=1`을 유지한다. 기능 rollback이
필요하면 먼저 배포·검증 진행을 멈추고 M5 source를 승인된 이전 기준점으로 되돌리되, 사용자
SQLite database와 queued outbox를 삭제하지 않는 것을 기본 원칙으로 한다. 같은 schema를
유지하므로 데이터 삭제나 downgrade migration은 M5 rollback의 선행 조건이 아니다.

`react-native-keyboard-controller`까지 제거하는 rollback은 단순 JavaScript source revert가
아니다. 별도 dependency/native 승인 뒤 manifest와 lockfile을 의도한 기준으로 수정하고 frozen
install, clean prebuild, iOS·Android Development Build를 모두 다시 수행해야 한다. 전후에는
package/lock hash, native autolinking, database schema·row count·integrity·fingerprint를 비교한다.
이 절은 복구 절차의 경계를 정의할 뿐 실제 rollback이나 데이터 삭제를 실행했다는 증거가 아니다.
Secrets, backup/restore, migration, rollback owner·trigger와 post-rollback health를 묶은 실행형
production template은 `docs/development-workflow.md` §6.1에 두며, M5에서는 실행하지 않았다.

## 12. 최종 종료 경계

M5의 로컬 채팅 읽기·쓰기 요구, 자동 품질 검사, native dependency integration, 두 플랫폼
Development Build/runtime database와 사용자의 keyboard/list/send 수동 수용은 완료됐다. 따라서
M5를 종료하고 다음 상태를 **M6 시작 전**으로 둔다.

이 종료는 local development 마일스톤의 종료다. 기존 dependency advisory와 production
variant·signing·backend/auth·물리 기기 및 접근성 미실행 항목 때문에 repository의 production
deployment readiness는 **NOT READY**로 유지한다.

이 종료는 M6 PLAN, 새로운 dependency, build 재실행, commit, push, PR 또는 remote write를
자동 승인하지 않는다. 다음 변경은 별도 사용자 승인 게이트에서 시작한다.
