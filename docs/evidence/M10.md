## 구현 경계

기본 주제 진입을 유지하고 서울 날짜는 T2 `today`, pagination은 서버 cursor를 사용한다.
제목으로 생성한 주제의 canonical `chatroom_id`로 기존 M8/M9 채팅에 진입한다. 생성 결과가
불확실하면 같은 UUID `Idempotency-Key`와 payload로 명시적으로 재시도하며 HTTP 409를 새 키로
자동 우회하지 않는다. 403/404/422 확정 거부 뒤에는 수정한 제목으로 새 시도를 할 수 있다.

작성자만 제목·본문을 수정하고 작성자 또는 그룹 소유자가 태그를 교체한다. 본문 공백·줄바꿈은
서버처럼 보존한다. 태그 전체 page를 확인한 뒤 교체하고 변경하지 않은 태그의 source/confidence를 유지한다.

Account DB migration 004는 주제/query cache를 추가하며 기존 메시지·outbox·checkpoint를 보존한다.
조회 전 capture한 `group_topics` marker의 해제와 검증된 캐시 저장은 같은 transaction에 묶인다.
실패·취소는 rollback하고 새 marker는 보존한다. UI는 shared session과 origin/U1 UUID/epoch 경계를 재사용한다.

기존 account sync의 기본 주제 알림·재연결·S1 commit 신호를 coalescing하여 목록을 재조회한다.
두 번째 WebSocket, WS cursor 직접 checkpoint 저장, 오프라인 주제 mutation queue는 추가하지 않는다.
T5/T6에는 별도 realtime event를 가정하지 않으며 다른 기기의 편집은 복귀·새로고침에서 재조회한다.

기존 [서버 OpenAPI](../../contracts/server/openapi.json)와
[`intake.json`](../../contracts/server/intake.json)의 source provenance를 유지했다.
[`contract.lock`](../../contracts/server/contract.lock)의 validator schema closure에 T1-T7을 추가했으며
계약 snapshot을 현재 배포 revision 검증이나 production-certified manifest로 바꾸지 않았다.
서버·homelab·legacy PWA는 수정하지 않았다.
