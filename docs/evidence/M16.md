## 3. 검증 중 발견과 조치

1. **Apple Developer 설정 누락 두 곳(요구사항 E21)**
   - App ID(`dev.local.jamyeapp`) Capabilities에 Sign in with Apple(Primary App ID)이 없어 로그인
     단계에서 8회 연속 `-24000 Invalid client`로 실패했다. 시뮬레이터 재시동으로는 해결되지
     않았다. 사용자가 Developer 포털에서 capability를 켠 뒤 바로 성공했다.
   - 서버가 쓰는 .p8 키의 Services에 Sign in with Apple이 없어(APNs·WeatherKit만 있었음), 계정
     삭제의 Apple 코드 교환이 두 차례 `apple_authorization_code_invalid`로 거부됐다(identity
     token 검증과 sub 일치는 통과, `/auth/token` 교환에서만 거부). 사용자가 같은 키에 Sign in
     with Apple을 추가했다 — Key ID가 같아 SOPS 값 재입력이나 재배포는 필요 없었다.
   - 두 설정 모두 M18 production bundle id에도 다시 필요하다. 점검 순서(App ID capability → 키
     Services → 기기 목록)를 문서화하는 것을 후속 후보로 남긴다(로드맵 "후속 후보" 참고).
2. **Android 에뮬레이터의 오래된 dev client**
   - 설치된 앱의 `lastUpdateTime`이 검증 시점보다 열흘 이상 앞서 있었다. APK에 `expo/modules/audio`
     가 없어 현재 JS를 실행하지 못하고 `Cannot find native module 'ExpoAudio'` 뒤 렌더 오류가
     났다. 에뮬레이터가 `default_boot` 스냅샷으로 예전 앱 상태를 되살린 것으로 보이며, M16 변경과는
     무관한 기존 환경 문제다.
   - 사용자 승인으로 외부 ADB 서버 종료 → native preflight → `expo prebuild --clean --platform
     android` → `expo run:android`로 재설치해 해결했다(빌드 성공, 약 1분 19초).
3. **계정 삭제가 실패해도 푸시가 꺼진 채 남는 결함(사용자 결정 U8·U9, `task-app-device` fix1)**
   - M15부터 있던 동작이 M16에서 Apple 재인증 실패 경로가 늘며 더 잘 드러났다. 원인은 앱이 삭제
     요청 전에 푸시 설치를 미리 해제한 데 있었다.
   - 수정: 삭제 전 해제를 없앴다 — 서버가 삭제 트랜잭션에서 push installation을 끄고, 앱은
     로그아웃 뒤 로컬 상태만 정리한다. 삭제가 실패하거나 취소되면 푸시는 그대로 남는다. 삭제 실패
     안내 두 가지(`그룹 소유권을 먼저 이전한 뒤 다시 시도해 주세요.`, `계정을 삭제하지 못했습니다.
     잠시 후 다시 시도해 주세요.`)는 인라인 문구 대신 제목 `계정 삭제`, 버튼 `확인` 하나의
     Alert(iOS 시스템 Alert, Android Material 다이얼로그)로 바꿨다.
   - 검사: `check:code` 0(238 suites / 2252 tests, architecture PASS, eslint 경고 15 기준선).
   - 재검증: 양 플랫폼에서 409 안내가 Alert로 표시됐고(사용자 스크린샷), `DELETE /api/v1/me` 409
     4회 앞에 push installation 삭제 요청이 없었다. live push installation은 kakao 2·google 2로
     유지됐고 users 3, 유예 0이었다.

## 4. 운영 데이터 규칙 (E20)

- 운영 쓰기는 검증용 Apple 계정의 가입, 로그인, 삭제(유예), 복구만 했다.
- 예외: 카카오·Google 계정 삭제 시도가 있었다(§2 항목 7, §3-3 재검증). 모두 서버가 409로 막아
  변경이 0이었다.
- DB는 읽기 전용 트랜잭션에서 개수만 조회했다: users, 유예 사용자, provider별 identity, refresh
  session, provider별 live push installation.
- Apple 이메일, 이름, 토큰, SOPS 값, 키 값은 조회하거나 기록하지 않았다. 로그는 method·route·
  status·범주형 error_code만 확인했다.
- 최종 집계: users 3, 유예 0, identity apple 1 / google 1 / kakao 1(모두 live).

## 7. 후속 과제

상세는 [로드맵](../roadmap.md)의 M16 "후속 후보"를 따른다. 요약:

- Apple 서버 간 알림(consent-revoked notifications) endpoint 도입 검토(범위 밖, 별도 승인 필요).

  규칙 추가(characterization test 선행).
