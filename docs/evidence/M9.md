## 구현 경계

화면은 account-scoped SQLite만 메시지 원본으로 읽는다. Migration 003은 outbox lease/retry와
event/checkpoint 저장을 추가한다. 재시도는 같은 `client_msg_id`·방·내용을 사용하며 REST
응답과 event 도착 순서가 달라도 하나의 canonical message로 수렴시킨다. REST 응답에
event cursor를 만들지 않고, 서버의 opaque cursor는 equality-CAS로만 갱신한다.

연결은 S1 → R1 ticket/socket → 구독 확인 → 두 번째 S1 순서로 누락 구간을 복구한다.
Socket이 열리면 초기 delta 완료를 기다리지 않고 heartbeat를 시작한다. Unknown event,
4001/4401, 426과 늦은 응답은 각 복구·권한 경계에서 처리한다. Logout/account 전환에서는
진행 중 요청·소켓·대기 작업을 세대 경계로 차단한다. Cold offline 시작은 U1로 계정을
확인하기 전 기존 account data를 노출하지 않는다.

계약은 server source `5decfbca9e719e7932a941e5af764cca3156f2f6`의 S1/R1과 선택된 realtime
schema/fixture를 수용했다. 원문 hash와 source provenance는
[`intake.json`](../../contracts/server/intake.json), validator closure는
[`contract.lock`](../../contracts/server/contract.lock)에 있다. Upstream의 `dirty` provenance를
production-certified manifest로 바꾸지 않았고, 이번 종료에서 서버나 homelab을 수정하지 않았다.
