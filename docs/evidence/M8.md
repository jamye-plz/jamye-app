# M8 실제 서버 REST 채팅 evidence

## 종료 상태와 범위

- 상태: `COMPLETED / USER_ACCEPTED`
- 종료일: 2026-09-10 — 양 플랫폼 사용자 확인 및 종료 기록·로컬 커밋 승인.
- 구현 범위: C1 주제 목록, C2 메시지 기록, C3 내 읽음 위치 저장, C4 텍스트 전송·수동 재시도.
- 실행 대상: `connected-auth` mode와 배포된 `https://jamye-api.ridewithmin.com`.
- 저장 경계: normalized API origin + U1 user UUID + session epoch, account-scoped SQLite.
- M0-M7의 과거 기록과 bootstrap/fixture 데이터는 보존한다.

그룹 상세에서 '주제 열기'를 눌러 목록과 기존 메시지 화면으로 진입한다. 사용자용 chatroom
명칭은 '주제', main room은 '기본 주제'다. API 경로와 내부 chatroom/topic 식별자는 변경하지 않는다.
페이지 조회·새로고침, 오류·수동 재시도, 한국어 입력과 기존 keyboard/list 동작을 연결했다.

서버 응답은 계약 검증과 domain mapping을 거쳐 SQLite에 적용하고 화면은 SQLite를 읽는다.
전송 전에 pending message와 outbox command를 함께 저장하며 수동 재시도는 같은 UUID
`client_msg_id`, 방과 내용을 사용한다. Local UI key와 server message ID는 분리한다.
계정·주제·화면 수명이 끝난 뒤의 늦은 결과를 차단하며, 취소가 이미 ack된 row를 failed로
되돌리지 않도록 회귀를 추가했다. 자동 재전송 dispatcher는 이번 범위에 없다.

C3에는 실제 화면에 보인 canonical message의 `message_id`를 보낸다. 서버가 대응하는
읽음 위치를 결정하며 앱이 pagination cursor나 local ID로 event cursor를 만들지 않는다.
읽음 결과 표시는 **내 읽음 위치 저장 성공**이지 상대방이 해당 메시지를 읽었다는 표시가 아니다.
