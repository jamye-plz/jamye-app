# M7 그룹·멤버십·초대 evidence

## 상태와 범위

- 세션: `20260909-183326`
- 상태: `COMPLETED / USER_ACCEPTED`
- 종료일: 2026-09-10 — 양 플랫폼 사용자 검증 확인 및 종료 기록·로컬 커밋 승인.
- 구현 범위: G1-G8, I1-I2; M8 chat, M9 realtime/outbox는 포함하지 않는다.
- 저장 경계: normalized API origin + U1 user UUID + M6 session epoch에 묶인 in-memory group store.
  SQLite fixture/bootstrap, SecureStore/MMKV cache와 M5 outbox는 변경하지 않았다.

구현된 여정은 connected-auth group list/create/join/detail/roster와 owner/member management다.
G2/G4 cursor는 opaque하게 전달하고 server order를 보존한다. mutation은 canonical 응답 뒤 targeted
refetch를 사용하며 optimistic membership/ownership merge를 하지 않는다. `membership_required`는
protected group을 비우고 list로 돌아가는 경로이고 `owner_required`는 membership을 유지한 채 권한을
다시 읽는 경로다. membership loss는 authorized REST 결과, self-leave/delete 성공,
foreground/manual refetch에서만 보장한다. WebSocket 즉시 eviction은 구현·검증하지 않았다.

이후 실행·사용자 수용 결과는 아래에 별도로 기록한다.

같은 그룹을 새로고침할 때 기존 상세·멤버 내용이 사라지는 문제는 model/UI 두 건의 실패로
재현한 뒤 수정했다. 로딩·일시적 실패에는 기존 내용을 유지하고 재시도를 제공하되, 다른 그룹이나
권한 상실 응답(403/404)에는 내용을 비운다. 가짜 bearer·초대 코드·서버 오류 원문 비로그 테스트는
원래 구현도 통과한 characterization이며 실제 정보 유출을 발견했다고 기록하지 않는다.
