## 4. 기기에서 찾은 결함과 수정

### 4.1 계정 DB v7 마이그레이션 실패로 주제·대화 저장소가 열리지 않음 (수정 완료)

- 증상: iOS에서 그룹 홈을 열면 `주제 저장소를 열지 못했습니다.`가 나왔다(사용자 보고). 운영
  API는 정상이었다.
- 원인(M15부터 있던 결함): expo-sqlite는 트랜잭션마다 새 연결을 여는데, 이 연결은 외래 키가
  기본값 OFF다. 그래서 대화방 정리·실패 메시지 버리기의 `ON DELETE CASCADE`가 한 번도 실행되지
  않아 고아 행이 쌓였고, 새 마이그레이션이 매번 실행하는 `PRAGMA foreign_key_check`에서 걸렸다.
- 수정(사용자 결정 U10 — 고아 행 정리만, 근본 원인은 후속): 마이그레이션 007이 재구성 전에
  applied_events → reconciliation_scopes → event_checkpoints → messages 순서로 고아 행을
  지운다. outbox 재구성은 메시지가 없는 command를 건너뛴다.
- 회귀 테스트: `media-expired-error-code-migration.bun.ts`의 `verifyDeviceOrphansAreRemoved`.
  RED(수정 전): `SQLite migration violated a foreign-key constraint.`, EXIT=1. GREEN: PASS.
  `tests/core/database/account` 12 suites / 61 tests PASS.
- 실제 DB 사본·기기 확인: 수정된 007을 기기 DB 사본에 적용하니 v7, FK 위반 0이 됐다(활성 계정
  outbox 16 → 15, 고아 1행 제거). 앱을 다시 실행한 뒤 iOS·Android 활성 계정 DB가 모두 v7로
  올라갔다.
- 후속 과제: 쓰기 연결에도 외래 키를 강제해야 한다. 켜기 전에 부모보다 자식을 먼저 쓰는 경로가
  있는지 점검이 먼저 필요하다(6절).

### 4.2 내가 보낸 공지 말풍선에서 주제 제목 링크가 보이지 않음 (수정 완료)

- 증상: iOS 기본 대화방에서 내가 쓴 공지의 제목 줄이 빈칸으로 보였다(`dev-05-ios-mainchat.png`).
- 원인: 링크 글자색이 `colors.primary`였는데 내 말풍선 배경도 같은 Berry였다.
- 수정: 링크가 말풍선 글자색을 물려받고 밑줄로 구분되게 했다(`chat-message-row.tsx`).
- 회귀 테스트: `chat-message-row.test.tsx`의 "in my own (primary) bubble the title stays
  readable". RED: 제목 링크 색이 말풍선과 같은 Berry(`#9B3F68`)였다. GREEN: 18/18.
- 기기 확인: Android 기기에서도 내 말풍선·받은 말풍선 모두 밑줄 제목이 잘 읽혔다(`dev-16`,
  `dev-28`).

### 4.3 iOS 주제 대화방 헤더가 `대화`로 멈추고 삭제 뒤에도 이전 제목이 남음 (수정 완료)

- 증상: 다른 멤버가 만든 주제 대화방 헤더가 `대화`로 나왔고(사용자 보고), 주제를 지운 뒤에도
  헤더 제목 버튼이 이전 제목 그대로 남았다(사용자 스크린샷).
- 원인 1: 대화방 목록을 불러온 뒤 다른 멤버가 만든 주제는 목록에 없는데, 제목 hook이 목록이
  준비돼도 다시 요청하지 않았다.
- 원인 2: 숨은 대화 화면과 요청이 경쟁했다. 대화방 목록·주제 상세 요청은 store에 하나뿐인데, 스택
  아래에 남은 다른 그룹의 대화 화면과 보이는 화면이 각자 자기 그룹 목록을 요청하면서 새 요청이
  앞 요청을 취소했다. 다른 그룹 목록에서 멈추면 보이는 화면은 다시 요청하지 않아 제목이
  `대화`로 고정됐다.
- 원인 3: 화면 옵션은 이전 값에 합쳐지는데, 삭제 분기가 `title`만 설정해 대화 화면이 먼저 설정한
  `headerTitle`(제목 버튼) 함수가 그대로 남았다.
- 수정: 목록에 없는 대화방은 한 번 더 불러오고, 목록·재요청·주제 조회 세 요청을 포커스된
  화면에서만 보내며, 삭제 분기가 `headerTitle`도 문자열 `삭제된 주제`로 덮어쓴다
  (`use-chatroom-title.ts`, `connected-chat-screen.tsx`).
- 회귀 테스트: `use-chatroom-title.test.tsx`, `connected-chat-screen.test.tsx`. RED: 4건 실패.
  GREEN: 13/13, `tests/features/chat` + `tests/features/topics` 46 suites / 410 tests PASS.
- 기기 확인: Android(계정 B)가 만든 주제 `M17 header fix2`를 iOS(계정 A)에서 열어 두고 Android가
  그 주제를 삭제하자, 약 4초 뒤 iOS 헤더가 `삭제된 주제`(제목 버튼 없음)로, 본문이
  `삭제된 주제입니다.`로 바뀌었다(`dev-53-ios-fix2-before.png`, `dev-54-ios-fix2-after.png`).

### 4.4 첫 화면으로 열린 초대 가입 화면이 닫히지 않음 (수정 완료)

## 5. 기기 검증 중 사용자 결정

### 5.1 U10 — 마이그레이션 007의 고아 행 정리만 먼저

4.1절 결함의 근본 원인(쓰기 연결의 외래 키 비활성)은 그대로 두고, 이번 마이그레이션은 쌓인
고아 행을 지우는 선에서 막기로 했다. 쓰기 연결에 외래 키를 강제하는 수정은 쓰기 순서 점검이
먼저 필요해 후속 과제로 남긴다(6절).

### 5.2 U11 — iOS 그룹 이름 변경을 Form 시트로

iOS 그룹 이름 변경을 swift-ui `Alert` 입력창에서 C3 `Form` 시트 route
(`groups/[groupId]/rename`, 새 주제와 같은 모양)로 바꿨다. 이유: `@expo/ui` 57.0.17의
`Button` role에 `confirm`이 없어 Alert의 기본 버튼을 Berry로 tint할 수 없었는데, 사용자는 확인
버튼도 네이티브 강조색이길 원했다. 시트의 `저장`은 새 주제와 같은 Berry `done` 버튼이다. Android는
기존 M3 `AlertDialog`를 그대로 쓴다. 시트는 루트 Stack modal이라 그룹 정보 화면이 blur되는데, 그
blur 한 번은 그룹 정보의 열린 detail을 닫지 않도록 처리했다(시트의 `renameGroup`이 그 detail에
대해 동작해야 하므로).

- 자동 확인: 관련 jest 3개 파일 31/31 PASS, typecheck·lint·architecture PASS.
- 기기 확인: 사용자가 iOS에서 시트를 열어 왼쪽 `취소`, 가운데 `그룹 이름 변경`, 오른쪽 Berry
  `저장`을 확인했고, 이름을 바꾸면 `저장`이 활성화됐다(사용자 스크린샷).

### 5.3 U12 — 그룹 정보 `관리` 섹션 재배치

사용자 요청으로 `관리` 섹션의 그룹 이름 변경과 초대 링크 공유를 다른 자리로 옮겼다(양

- 이름 변경: 상단 요약의 그룹 이름을 누르면 편집한다. 소유자에게만 이름 오른쪽에 연필
  아이콘이 보인다(`group-name-heading.tsx`).
- 초대 링크 공유: 헤더 오른쪽 위 네이티브 공유 버튼(iOS SF `square.and.arrow.up`, Android
  Material `share`)으로 바꿨다. 서버가 초대 생성을 소유자에게만 허용하므로 공유 버튼도
  소유자에게만 보인다.
- `관리` 섹션과 "초대 링크 만드는 중…" 행은 없앴다.

### 5.4 U13 — 공지 링크로 연 주제 상세의 뒤로가기 순서

그룹 대화방의 공지 링크로 주제 상세를 열면, 상세가 자기 주제의 대화방 ID를 알게 되는 즉시
상세 바로 아래 화면을 그 그룹 대화방에서 그 주제의 대화방으로 바꾼다(`navigation.reset`으로
맨 위 상세의 key는 유지하고 아래 경로만 교체). 그 결과 그룹 홈에서 연 그룹 대화방이라면 뒤로가기 순서는 주제 상세 → 주제 대화방 → 주제
목록이 된다. 주제를 불러오기 전에 뒤로 가면 그룹 대화방으로 돌아가고, 그룹 대화방을 알림함에서
열었다면 주제 대화방 다음은 알림함이다. 주제 대화방에서 제목을 눌러 연 상세와 삭제된
주제(대화방 없음)는 영향받지 않는다.

- 회귀 테스트(`topic-detail-screen.test.tsx`, "M17/U13" 3건): RED — hook 호출 누락 시
  `Expected number of calls: 1, Received: 0`. GREEN: 13/13, `tests/features/topics`
  17 suites / 157 tests PASS.
- 기기 확인: Android(coordinator)에서 그룹 대화방 → 공지 링크 → 주제 상세(`dev-69`) → 뒤로 →
  주제 대화방(`dev-70`) → 뒤로 → 주제 목록(`dev-71`). iOS는 사용자가 같은 흐름을 확인했다.

## 6. 한계와 후속 과제

- 주제 공지 형식 흉내(VERIFY Step 7b, 사용자 결정 U14): 서버는 공지를 일반 `kind='user'`
  메시지로 저장하고, 앱은 본문 형식만 보고 제목을 링크로 그린다. 그래서 그룹 구성원이 같은
  형식의 본문을 직접 보내면 공지처럼 보이는 링크가 된다. 링크는 앱 안의 주제 경로로만 이동하고
  도착 화면이 권한을 다시 확인하므로 데이터 노출은 없다. 서버가 공지 구분값을 계약에 더하는
  후속으로 남긴다(로드맵 M17 (C)).
- 쓰기 연결 외래 키 강제: expo-sqlite의 새 연결은 외래 키가 기본 OFF다(4.1절). 쓰기 연결에
  `PRAGMA foreign_keys = ON`을 강제하기 전에, 부모보다 자식을 먼저 쓰는 기존 경로가 있는지
  점검이 먼저 필요하다.
- 과거 공지 소급 숨김 불가: 이번 업데이트 이전에 이미 처리된 `topic.deleted`는 로컬 이벤트
  기록에 공지 메시지 id가 남지 않아 식별할 수 없다. 새로 도착하는 `topic.deleted`만 처리된다
  (CHAT-AC2).
- Android 캐러셀 가장자리 항목이 여전히 사각: M3 캐러셀의 item mask가 RN 콘텐츠에 닿지 않고
  `@expo/ui`에 이를 조정할 API도 없다. 앱 쪽 고정 12dp 모서리는 완전히 보이는 항목에만 맞고,
  축소되는 항목은 기기에서 사각으로 잘려 보인다(사용자 결정 U7).
- 에뮬레이터 세션 복원이 3초 안전 타임아웃보다 느림: 이번 세션 측정으로 복원에 약 6초가 걸려
  로그인 화면이 잠깐 보였다. 복원 로직 자체는 M17 변경 밖이다. 실기기 복원 시간을 다시 재고,
  필요하면 복원 중 중립 화면이나 저장 순서 조정을 검토한다.
- Android 동영상 업로드 실패: 에뮬레이터 녹화(2.5MB H.264) 업로드가 네이티브 PUT(120초
  타임아웃)에서 끝나지 않아 실패했고 재시도도 실패했다(같은 경로의 사진 업로드는 성공). M17이
  바꾸지 않은 경로라 별도 조사가 필요하다.
- 뷰어 닫기 버튼 위치 불일치: 갤러리에서 연 사진 뷰어는 닫기가 오른쪽에 있고, 대화방 페이저
  뷰어는 닫기가 왼쪽·공유가 오른쪽이다. 기존 동작이며 UX 일관성 후속이다.
- 주제 목록 오프라인 오류 문구 중복: 전체 화면 오류 상태의 제목(`주제를 불러오지 못했습니다.`)과
  설명 첫 문장이 같다. 문구 다듬기 후속이다.
- Android 뷰어 닫기 스와이프는 adb `input swipe`/`motionevent`로는 재현되지 않았다(사람 손가락·
  마우스 드래그로는 확인됨, §3-4). M17이 만든 회귀는 아니지만 자동화 재현 수단은 남는 과제다.
- `auth-controller.ts` 분리 이후에도 `max-lines-per-function` lint 규칙은 추가하지 않았다
  (로드맵 F 묶음 참고).
