## 6. 기기 결함 1–10 요약

1. **(수정) Android 목록 행 삭제 직후 크래시** — `action-list-item.android.tsx`가 RN 콘텐츠를
   `RNHostView matchContents` 없이 Compose `ListItem` 슬롯에 넣어 `LazyColumn` 재사용 시 충돌.
   수정: `RNHostView matchContents`로 호스팅. 회귀 테스트 5/5.
2. **(수정) 상세 헤더 삭제 확인창이 `Host` 밖에서 렌더** — `AlertDialogView must be rendered as a
   direct child of a <Host>`. 수정: `<Host matchContents seedColor>`로 감쌈. 회귀 테스트 7/7.
3. **(수정, HIGH) 삭제된 주제의 열린 대화방이 홈으로 튕김** — 열린 방 하나의 접근 상실을 그룹 단위
   상실로 잘못 판정. 수정: 채팅 스토어가 방 단위 상실(`roomAccessLost`)과 그룹 단위 상실을 구분
   (`task-app-chat` r2).
4. **(수정, LOW) 삭제된 주제 상세에 헤더 ⋮가 남음** — 편집 중이 아닐 때 항상 렌더 후 빈 배열로
   지우도록 수정(`task-app-topics` r2).
5. **(수정, HIGH) 삭제된 대화방 동기화 무한 루프** — 로컬 방 목록이 서버에서 사라진 방을 정리하지
   않음. 수정: 열린 방 상실 시 동기화 제외, `pruneChatroomsNotIn`으로 서버에 없는 로컬 방을
   FK cascade로 정리(`task-app-chat` r2).
6. **(수정, MEDIUM) 읽음 처리 422** — 삭제 표시 행을 anchor로 사용하던 문제. 수정: 살아 있는
   메시지를 anchor로 선택(`task-app-chat` r3).
7. **(수정, MEDIUM) iOS 스와이프 삭제가 확인 전에 행을 지움** — SwiftUI destructive role이 확인
   전에 행 삭제 애니메이션을 실행. 수정: 스와이프는 빨간 tint, 컨텍스트 메뉴는 destructive role
   유지(`task-app-topics` r3).
8. **(수정, 3차 배포) `topic.deleted`가 전달되지 않음** — 곧 삭제되는 주제 대화방 피드에 기록돼
   S1 403·WS 필터로 아무도 받지 못함. 수정: 그룹 메인 대화방 피드에 기록(`task-srv-14c`, 3차 배포
   `6dcb6d5`).
9. **(수정, LOW) 로그아웃/계정 삭제 전환 중 Compose `modifiers` 오류** — 진행 중 `ListItem`의
   `onPress`를 `undefined`로 바꿔 네이티브 prop 캐스팅이 실패. 수정: `onPress`를 항상 정의된
   함수로 유지하고 핸들러 내부에서 진행 중이면 조기 반환(`task-app-account` r2).
10. **(수정·기기 확인, 한계 있음) 탈퇴한 사용자의 삭제된 메시지가 이름·사진 유지** — C2는 삭제된
    메시지를 다시 주지 않아 로컬 삭제 표시가 동결됨. 수정: C2 응답의 보낸 사람 표시를 같은 사용자의
    로컬 행 전체에 전파(`task-app-chat` r3), 주제 작성자 신원도 전파 출처로 추가(`task-app-chat`
    r4, AC8). 남는 한계는 §7.

관찰(LOW, 기능 문제 아님): 삭제 상태 대화방 헤더에 주제 제목이 남음, 내 삭제 행의 시간 표시가
iOS(없음)/Android(`시간 · 전송됨` 유지)에서 다름.

  활성화·알림함 열기 때 갱신(시뮬레이터·에뮬레이터 dev 빌드는 푸시 미수신이라 더 눈에 띔).
