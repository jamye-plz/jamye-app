# Jamye App Design Context

## Project

- **Name**: jamye-app
- **Type**: React Native and Expo mobile chat application
- **Current slice**: One local fixture conversation backed by SQLite
- **Platforms**: iOS and Android development builds
- **Language**: Korean only for the current product surface

## Target Audience

- Close friends and acquaintances in a small private group
- People who open the app briefly and often to continue an existing conversation
- A general consumer audience that should not need technical knowledge
- Users of Korean system keyboards, VoiceOver, TalkBack, Dynamic Type, and large Android font scales

## Brand Personality

- Warm, private, playful, and conversational
- Friendly without turning the message surface into decoration
- Trustworthy about local writes and visible send state
- Plain and direct in status and recovery copy

## Aesthetic Direction

- **Chosen direction**: Native pastel conversation board
- **Mood**: Warm paper, low-chroma surfaces, berry emphasis, quiet depth
- **Theme**: System-driven light and dark palettes authored independently
- **Density**: Comfortable message rhythm with compact same-sender grouping
- **Motion**: Minimal; only system-owned keyboard progress and the committed-message reveal move conversation content
- **Accent lock**: The berry primary role is the only interactive accent
- **Radius lock**: Soft radius ladder with a directional message corner

## Typography

- Use the React Native platform system font for Korean text in M5.
- Do not add a font package or font asset solely for M5.
- Preserve 16px-equivalent message text at 1.55 line height and 13px-equivalent metadata.
- Keep body and input copy at 16px-equivalent minimum and allow system font scaling.
- Pretendard remains a future brand option, not an M5 dependency.

## Color Direction

- Outgoing messages use the existing berry `primary` and `onPrimary` roles.
- Incoming messages use the existing neutral raised `surface` role.
- Page, text, border, error, notice, and muted values come from `src/core/theme/tokens.ts`.
- Light and dark palettes are not generated by inversion.
- System status-bar content follows the active theme: dark content over the light canvas and light content over the dark canvas on both platforms.
- Status never relies on color alone.

## Interaction Direction

- Enter or Return inserts a newline. It never sends.
- Only the explicit send button submits a message.
- Korean IME composition and the draft survive intermediate composition events and failed writes.
- The message list is not inverted. Older-page loading occurs at the top edge and retains the visible anchor.
- The platform keyboard frame owns keyboard overlap and bottom-safe-area normalization. The message list consumes the same native progress signal so its lower visible boundary moves continuously with the keyboard.
- When the keyboard opens or closes, the latest visible message remains directly above the composer. Do not approximate native timing with JavaScript timers or repeated layout-event corrections.
- A successful explicit send clears the committed draft while preserving input focus and the keyboard. After the committed row is laid out, reveal that local message completely; incoming messages do not force this behavior.
- Shared UI owns semantics and tokens. Small iOS and Android wrappers may adapt keyboard progress only; both platforms keep the same anchor contract.

## Approved Copy

- Main heading: `로컬 대화`
- Pending: `전송 중`
- Failed: `전송 실패`
- Sent: `전송됨`
- Failed message retry: `메시지 다시 보내기`
- Older page retry: `이전 메시지 다시 불러오기`
- Initial message loading: `메시지 불러오는 중...`
- Initial message error: `메시지를 불러오지 못했습니다.`
- Initial message retry: `메시지 다시 불러오기`
- Successful empty conversation: `아직 메시지가 없습니다.`
- Message region: `채팅 메시지`
- Composer input: `메시지 입력`
- Send action: `메시지 보내기`
- Connection retry copy `다시 시도` is reserved for M6 and is not used in M5.

## Accessibility

- WCAG 2.2 AA is the minimum design target.
- Interactive targets are at least 44x44 points.
- Status is communicated with exact text and semantic state, never color alone.
- The main heading receives predictable initial focus before ordinary reading order.
- Reading order is heading, local-fixture notice, messages, composer, and send action.
- A send-state live announcement occurs only when the state actually changes.
- The layout must remain usable at 200% text, in dark mode, and with reduced motion.

## Redesign Audit

- **Mode**: Redesign - Preserve
- **Preserve**: warm paper canvas, berry conversation accent, neutral incoming surface, Korean copy, accessible state text, message rhythm, IME safety, scroll-anchor intent
- **Translate for native**: safe areas, keyboard behavior, VoiceOver and TalkBack order, platform font scaling, Pressable feedback
- **Retire from the web implementation**: Svelte, daisyUI, CSS variables, browser viewport correction, desktop rails, connection UI, media controls, web animation primitives
- **Information architecture**: one thin route and one fixture conversation in M5; no new navigation structure
- **SEO baseline**: not applicable to this native application slice
- **Assets**: no imagery is required for the M5 conversation screen; do not create decorative placeholders
